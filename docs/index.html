ugnas-mcp

A generic MCP server for UGREEN NAS devices running UGOS, talking over SSH with SFTP for transfers. Nothing is hard-coded — no fixed IPs, subnets, usernames, or share names. Every target-specific value comes from your config, so the same server works for anyone's NAS.

  • 39 tools
  • TypeScript · ESM
  • Node ≥ 20
  • stdio + HTTP transport
  • MIT license

What it does

Organized the way a NAS owner actually thinks about daily operations — five tool groups, one module per group in the source, each taking the same service context.

🩺

Connection & system

Connectivity check, OS/hardware info (CPU, memory, temps, disks), and storage pool health across mdadm RAID, LVM, btrfs, and block devices.

🐳

Docker

Full container lifecycle: list, inspect, logs, start, stop, restart, remove. Images (list/pull/remove), networks (list/inspect/create/remove/connect/disconnect), and docker compose up/down/restart.

📂

Files & data

Browse, measure, and search shares; upload/download over SFTP (chroot-aware); rsync-style sync with a built-in cp fallback; thumbnails rendered with ffmpeg on the NAS.

💾

Backup

Create tar.gz archives on the NAS, list and verify them (checksum + entry count), restore into a destination, and install managed recurring cron jobs — preserving any existing non-managed crontab entries.

🛰️

Networks

Interface inventory with IPv4/IPv6 addresses and scopes, IPv4/IPv6 routing tables, and listening TCP/UDP sockets with the processes bound to them.

🛡️

Dry-run safety

Every mutating tool plans first. You review the exact shell commands it would run, then confirm with a single-use, action-bound, 10-minute token. See the safety model.

Safety model — dry-run first, then confirm

Every mutating tool has two phases. Read-only tools never need a token. This makes "copy my data", "pull this image", or "restart that container" reviewable before anything changes.

┌──────────────────────────────────────────────────────────────────┐ │ MCP client ugnas-mcp NAS over SSH │ └──────────────────────────────────────────────────────────────────┘ 1. files.remove { path: "media/old" } no mutation │ ▼ plan: rm -rf '/volume1/media/old' ──► returns dry-run plan │ + confirmationToken ▼ (single-use, 10 min) 2. review the plan yourself ──► approve? │ │ ▼ no ▼ yes do nothing files.remove { path: …, confirmToken } │ │ ▼ ▼ done. executes exactly the commands captured at plan time — verbatim. (args are cross-checked: a token issued for different arguments is refused.)
🔒

Injection-proof by construction. All user-supplied values (paths, container names, image tags) are POSIX-shell-quoted before being interpolated into remote commands. Backup job names are restricted to [A-Za-z0-9._-] and cron expressions are validated as exactly five fields — they end up inside shell scripts and crontab lines. Pinned host-key fingerprints are compared padding-insensitively, so the canonical ssh-keygen -lf output works as-is.

🧾

At confirm time, arguments are cross-checked. The token stores the plan-time payload; if the confirming call's arguments differ, the tool refuses and asks you to re-run for a fresh plan. A stale token can never execute a differently-argued action.

Architecture

A small, layered codebase — one module per tool group, a narrow SSH executor interface (so tests run against a fake, no real NAS needed), and a single confirmation service. 

src/
├── server.ts          entrypoint: stdio transport + optional stateless HTTP (/mcp, /health)
├── config.ts          zod-validated config (~/.ugnas-mcp/config.json or UGNAS_* env overrides)
├── mcp/
│   ├── createServer.ts    McpServer wrapper
│   └── toolset.ts         all 39 tool registrations
├── safety/plan.ts    ConfirmationTokenService — the dry-run/confirm core
├── ssh/
│   ├── sshExecutor.ts     CommandExecutor interface + ssh2-backed SshExecutor
│   └── shellQuote.ts      shq() POSIX quoting — every user value passes through it
└── services/         one class per tool group, each takes ServiceContext
    ├── systemService    status / info / pools (mdadm, LVM, btrfs, lsblk, blkid parsers)
    ├── dockerService    containers / images / networks / compose
    ├── fileService      list / usage / find / thumbnail / mkdir / copy / move / remove
    │                    / upload / download / sync (rsync or cp fallback)
    ├── backupService    create / list / verify / restore / schedule (managed crontab)
    ├── networkService   interfaces / routes / ports
    └── util.ts          planOrExecute, path resolution, output parsers
⚡

One SSH round-trip for many reads. Read-heavy tools batch their commands with ###NAME### markers and parse the sections out of a single round-trip — e.g. system.info gathers OS release, CPU, load, memory, uptime, temperatures, disks, and Docker version in one call.

📦

UGOS SFTP chroot awareness. UGOS chroots SFTP to the share root, so an exec path like /volume1/docker/x must be requested over SFTP as /docker/x. The sftpRoot config handles the mapping; thumbnails are fetched via base64-over-exec since /tmp sits outside the chroot.

🐧

BusyBox-friendly. GNU-only flags (ls --time-style, find -printf) are probed once and cached; on BusyBox the file tools fall back to ls -1p and find -exec stat so they keep working either way.

Configuration

The server reads a JSON config from ~/.ugnas-mcp/config.json (override with UGNAS_MCP_CONFIG). Environment variables win over the file — useful for CI or secret injection: UGNAS_HOST, UGNAS_PORT, UGNAS_USER, UGNAS_KEY_PATH or UGNAS_AUTH_TYPE=password + UGNAS_PASSWORD, UGNAS_DEFAULT_SHARE, UGNAS_HOST_KEY_SHA256. 

{
  "name": "home-nas",
  "host": "192.168.1.50",
  "port": 22,
  "username": "admin",
  "auth": { "type": "key", "privateKeyPath": "~/.ssh/id_ed25519" },
  "defaultShare": "/volume1",
  "commandTimeoutMs": 60000
}

Wiring it into an MCP client (stdio)

{
  "mcpServers": {
    "ugnas": {
      "command": "node",
      "args": ["/absolute/path/to/ugnas-mcp/dist/src/server.js"],
      "env": { "UGNAS_MCP_CONFIG": "/absolute/path/to/config.json" }
    }
  }
}

Optional HTTP transport

stdio by default. Set UGNAS_HTTP_PORT to also expose a stateless streamable HTTP transport at /mcp (max 1 MiB body) plus /health. It binds to loopback; a non-loopback UGNAS_HTTP_HOST is refused unless UGNAS_HTTP_ALLOW_REMOTE=1 — the endpoint has no authentication, so only opt in behind something that adds auth (reverse proxy, VPN). 

UGNAS_HTTP_HOST=127.0.0.1 UGNAS_HTTP_PORT=4110 node dist/src/server.js

POST http://127.0.0.1:4110/mcp     # JSON-RPC (stateless)
GET  http://127.0.0.1:4110/health  # liveness + target host

Prerequisites on the NAS

SSH

Enabled on UGOS via Control Panel → Terminal & SNMP.

Docker group

The SSH user must be in the docker group; crontab access for scheduled backups.

Standard tools

tar, df, du, ip, ss — all present on UGOS.

Optional

rsync (only files.sync; cp fallback otherwise) and ffmpeg (only files.thumbnail).
